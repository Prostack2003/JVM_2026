# ADR 010: наблюдение через интерфейсный proxy

**Статус:** принято для практики 10.

## Контекст

Нужно показать русские метаданные public-операций и считать отдельные обращения, сохранив прикладные правила, результаты и типы исключений практики 09.

## Решение

- выделить `NutritionPlanOperations`, реализуемый `NutritionPlanService`;
- поместить runtime-аннотацию на два метода интерфейса;
- читать описания только через `getMethods()`/`getAnnotation()`;
- создать стандартный JDK dynamic proxy в точке сборки приложения;
- учитывать только методы с аннотацией и не сохранять аргументы;
- обслуживать методы `Object` отдельно;
- раскрывать `InvocationTargetException` и выбрасывать `getCause()`.

## Последствия

UI зависит от стабильного интерфейса, а наблюдение можно включить или убрать в `ApplicationContext`. Бизнес-валидация остаётся в модели и сервисе. Неуспешная попытка отмеченной команды попадает в счётчик, но клиент получает исходное исключение. Цена решения — дополнительный интерфейс и необходимость хранить метаданные именно на нём.

Отклонён вариант универсального вызова метода по строке: он расширяет поверхность ошибок и не нужен для диагностики. Отклонено автоматическое копирование полей через reflection: оно не связано с задачей и разрушает явные предметные границы.
