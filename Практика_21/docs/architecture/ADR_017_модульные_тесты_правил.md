# ADR 017: модульные тесты правил NutritionPlan

## Статус

Принято для практики 17.

## Контекст

Правила допустимого плана питания принадлежат предметной модели. Проверка через JavaFX, SQLite или HTTP добавила бы причины отказа, которые не связаны с инвариантами записи.

## Решение

- Проверять `NutritionPlan` обычными JUnit-тестами без внешних адаптеров.
- Давать каждому тесту одну наблюдаемую причину неуспеха.
- Параметризовать варианты пустого имени как один контракт.
- Использовать фиксированную дату и новую фикстуру в каждом сценарии.
- Подтвердить полезность ключевого теста временной мутацией и вернуть рабочий код до финальной проверки.

## Последствия

Набор быстро локализует нарушение правила и не зависит от порядка. Он не доказывает работу SQLite, FXML или HTTP: эти риски остаются за интеграционными тестами соответствующих адаптеров и полным `check`.
