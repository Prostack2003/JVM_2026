# Объяснение решения и границы этапа

## Источник истины

Источником истины для таблицы и счётчика является один `ObservableList<NutritionPlan>` внутри `NutritionPlanService`. Сервис возвращает неизменяемое наблюдаемое представление того же объекта. Интерфейс получает уведомления, но не может добавить, удалить или заменить запись в обход прикладной операции.

Метка количества связана с `Bindings.size(service.plans())`. Обработчики не хранят отдельное числовое поле и не меняют текст счётчика вручную.

## Добавление и удаление

При добавлении сервис проверяет название, создаёт план и вызывает `add` наблюдаемого списка. Таблица и счётчик получают одно событие об изменении состава.

Удаление доступно только при выбранной строке. Это состояние вычисляется привязкой к `selectedItemProperty`. После успешного удаления выделение очищается, поэтому оно не может указывать на уже отсутствующий объект.

## Замена неизменяемой записи

`NutritionPlan` остаётся неизменяемой записью. Смена состояния вызывает `withStatus`, затем сервис выполняет `set` по индексу исходного элемента. Событие замены обновляет нужную строку таблицы без `refresh()` и без повторного заполнения всего списка.

## Сравнение способов обновления

| Способ | Недостаток | Выбранное решение |
|---|---|---|
| Повторно заполнить таблицу | Лишняя работа, возможная потеря выбора и состояния таблицы | Не используется |
| Вручную менять текст счётчика | Возникает вторая копия значения, которую легко забыть обновить | Не используется |
| Привязать счётчик к наблюдаемому списку | Требует одного устойчивого источника данных | Используется |

## Предметный отрицательный сценарий

Названия планов уникальны без учёта регистра. Попытка добавить `поддержание МАССЫ`, когда уже есть `Поддержание массы`, оставляет таблицу и счётчик без изменений и показывает объяснение. Это предотвращает появление двух визуально одинаковых планов текущего сеанса.

## Почему записи исчезают после закрытия

Наблюдаемый список находится только в памяти JVM. Каждый новый запуск создаёт сервис заново с одной исходной записью. Постоянное хранение появится на последующих этапах курса.

## Ограничения

- операции выполняются только в текущем процессе;
- экран собран программно, FXML и CSS появятся на следующем этапе;
- база данных, файлы, HTTP и существующий backend не используются;
- сортировка и фильтрация таблицы не входят в это занятие.
