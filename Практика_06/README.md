# Практика 06. Наблюдаемые данные, таблица и привязки

Самостоятельный проект на Java 25 и JavaFX 25 в предметной области дневника питания КБЖУ. Таблица, счётчик строк и доступность действий зависят от одного наблюдаемого списка планов питания.

## Что реализовано

- `ObservableList<NutritionPlan>` служит единственным источником данных таблицы;
- счётчик `Планов: N` вычисляется привязкой `Bindings.size`, без ручного увеличения и уменьшения;
- добавление сразу отражается в `TableView` и счётчике;
- удаление выбранной строки уменьшает счётчик и очищает выделение;
- кнопка удаления недоступна, когда строка не выбрана;
- смена состояния выполняется заменой неизменяемой записи результатом `withStatus`;
- пустой список показывает предметную подсказку и значение `Планов: 0`;
- пустое название отключает добавление;
- повторное название без учёта регистра отклоняется без изменения списка;
- публичное представление списка наблюдаемо, но не позволяет обходить операции сервиса.

## Требования

- полный JDK 25;
- Linux, macOS или Windows с графической средой;
- доступ к Интернету при первой загрузке Gradle, JavaFX и JUnit.

Проверка среды:

```shell
java -version
javac -version
```

## Сборка и тесты

Из папки `Практика_06` выполните:

```shell
./gradlew clean check
```

Для Windows:

```text
gradlew.bat clean check
```

## Запуск окна

```shell
./gradlew run
```

Для Windows:

```text
gradlew.bat run
```

Точка входа: `src/main/java/ru/npi/kbju/Launcher.java`. Жизненный цикл окна реализован в `src/main/java/ru/npi/kbju/ui/DesktopApp.java`.

Короткий фактический запуск окна завершается самостоятельно:

```shell
./gradlew run --args=--smoke
```

## Воспроизводимая проверка интерфейса

Служебная задача запускает настоящее JavaFX-окно, выполняет добавление, замену состояния, удаление, отказ на дубликате и переход к пустому списку. Снимки сохраняются в `docs/evidence`:

```shell
./gradlew captureEvidence
```

После первой загрузки зависимостей весь комплект проверяется без сети:

```shell
./gradlew --offline clean check captureEvidence
./gradlew --offline run --args=--smoke
```

## Ручной сценарий

1. Запустите приложение. Убедитесь, что показана одна строка, счётчик равен `Планов: 1`, а удаление недоступно.
2. Введите `Поддержание массы` и добавьте план. Таблица и счётчик должны увеличиться на одну строку.
3. Выберите строку `Снижение массы` и нажмите `Сделать активным`. Число строк не изменится, а состояние станет `Действует`.
4. Удалите выбранную строку. Счётчик уменьшится, выделение очистится, удаление снова станет недоступно.
5. Повторно введите существующее название в другом регистре. Список не изменится, появится объяснение отказа.
6. Удалите последнюю строку. Таблица покажет пустое состояние, счётчик станет равен нулю.

## Почему таблица обновляется

`NutritionPlanService` владеет изменяемым `ObservableList`, а наружу отдаёт неизменяемое наблюдаемое представление того же списка. `TableView` и `Bindings.size` подписаны на его события. Добавление, удаление и `set(index, replacement)` автоматически уведомляют оба потребителя, поэтому отдельный счётчик и вызов `refresh()` не нужны.

## Структура

- `domain/NutritionPlan.java` — неизменяемая запись и `withStatus`;
- `application/NutritionPlanService.java` — единственный наблюдаемый список и операции над ним;
- `ui/NutritionPlanView.java` — таблица, привязки и обработчики действий;
- `ui/DesktopApp.java` — создание `Stage` и `Scene`;
- `docs/decision.md` — сравнение способов обновления и границы решения;
- `docs/check-protocol.md` — ожидаемые и фактические результаты;
- `docs/evidence/` — выводы команд и снимки JavaFX.

Практика не использует FXML, CSS, базу данных, HTTP или существующий TypeScript-backend.
