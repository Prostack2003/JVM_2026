# Протокол чистого запуска

## Цель

Доказать, что app-image работает без IDE, каталога исходников и внешнего JDK, загружает ресурсы и сохраняет данные между процессами.

## Автоматизированный маршрут

1. `packageAppImage` создаёт образ в `build/package`.
2. `verifyAppImage` проверяет launcher, runtime, JAR и ресурсы.
3. `verifyPackagedLaunch` создаёт два независимых временных каталога: для копии образа и для данных.
4. Всё дерево `KbjuDiary` копируется в первый каталог; рабочий каталог процесса указывает туда же.
5. Launcher запускается с `--data-dir=<второй каталог> --package-probe=add`.
6. JavaFX загружает FXML и CSS, форма создаёт план «Приёмка app-image», SQLite содержит две строки.
7. Первый процесс завершается, затем тот же launcher запускается с `--package-probe=verify`.
8. Второй процесс находит две строки и сообщает путь `java.home` внутри копии образа.
9. Проверяется существование SQLite во внешнем каталоге данных и отсутствие базы внутри образа.
10. Временные каталоги удаляются в блоке `finally`.

## Ручное повторение

```shell
./gradlew --offline verifyDistribution
mkdir -p /tmp/kbju-clean
tar -xzf build/distributions/KbjuDiary-23.0.0-linux-amd64.tar.gz -C /tmp/kbju-clean
/tmp/kbju-clean/KbjuDiary/bin/KbjuDiary --data-dir=/tmp/kbju-user-data
```

В открытом окне нужно добавить запись, закрыть приложение и запустить ту же команду повторно. Запись должна сохраниться в `/tmp/kbju-user-data/data/nutrition-plans.db`.

## Критерий отказа

Ненулевой код процесса, тайм-аут 45 секунд, отсутствие FXML/CSS, неверный `java.home`, невозможность добавить запись или потеря записи при повторном запуске завершают Gradle-задачу ошибкой.
