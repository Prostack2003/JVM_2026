# ADR 016: кэш, retry и TTL внешнего справочника

## Статус

Принято для практики 16.

## Контекст

Справочник продуктов полезен без сети, но пользователь должен знать, что видит копию, и оценивать её возраст. Общий `catch` с fallback на любой отказ может скрыть отзыв доступа или поломку контракта. Прямая запись в единственный файл может уничтожить прежнюю рабочую копию.

## Решение

- Прикладной сервис зависит от портов `ProductDirectory` и `ProductCatalogCache`.
- Кэш хранит только полный проверенный список и `receivedAt`.
- Файл заменяется только после записи временной копии.
- Кэш допустим на границе 24 часов и недопустим после неё. Время передаётся через `Clock`.
- Retry ограничен двумя попытками и разрешён только для временных отказов идемпотентного GET.
- Атомарный флаг не позволяет запустить два обновления одновременно.
- `CatalogSnapshot` всегда содержит `source`, `receivedAt`, `age`, число попыток и, для кэша, причину fallback.

## Последствия

Правила TTL, retry и fallback проверяются без окна, сети Интернет и реального ожидания. При повреждённом ответе рабочий файл остаётся на диске, но поломка контракта не скрывается автономным режимом. Учебная политика не учитывает `Retry-After` и не добавляет jitter; это осознанное ограничение.
