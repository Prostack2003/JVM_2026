# ADR-018: портфель интеграционных и UI-проверок

**Статус:** принято.

## Контекст

Модульные тесты предметных правил не доказывают упаковку FXML, связь кнопки с обработчиком и корректность настоящей SQLite. Один длинный сквозной тест смешал бы причины отказа и усложнил диагностику.

## Решение

- сохранять быстрые проверки `domain` и `application`;
- проверять SQLite на уникальном временном файле с повторным открытием;
- проверять FXML отдельно как classpath-ресурс и содержимое JAR;
- защищать один критический маршрут через реальные FXML-контролы, сервис и изолированный memory adapter;
- выполнять действия JavaFX в FX Application Thread и ожидать их завершения через сигнал с тайм-аутом;
- оставлять внешний вид, масштабирование и платформенную доступность ручной проверке.

## Последствия

Отчёт указывает компонент, на границе которого возник отказ. UI-сценарий остаётся коротким, а SQLite-проверка не затрагивает пользовательскую базу. Для автоматического JavaFX-теста нужен доступный графический сеанс; зелёный результат не доказывает одинаковый вид на каждой ОС.
