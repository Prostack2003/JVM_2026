# ADR 023: Kotlin для изолированного форматировщика

- Статус: принято.
- Дата: 4 октября 2026 года.

## Контекст

Практика требует доказать совместимость Java и Kotlin без переписывания работающего приложения. Наиболее безопасная граница дневника КБЖУ — чистое представление неизменяемого `NutritionPlan` в строку.

## Решение

Реализовать `NutritionPlanCaption` как Kotlin `object` с методом `@JvmStatic format(NutritionPlan?)`. Java вызывает метод напрямую. Kotlin использует существующий Java-record и enum. `null` отклоняется через `requireNotNull` с устойчивым сообщением.

Kotlin Plugin и stdlib фиксируются версией 2.4.10. JPMS-модуль явно читает `kotlin.stdlib`, а `compileJava` получает Kotlin output через `--patch-module`.

## Последствия

- оба направления взаимодействия языков видны в одном коротком сценарии;
- JVM-сигнатура и null-поведение проверяются автоматически;
- `installDist` становится больше на Kotlin stdlib;
- UI, БД и предметные правила не получают риска миграции;
- сборка требует Kotlin Gradle Plugin, который загружается при первой подготовке.

## Отклонённые варианты

- переписать `NutritionPlan` на Kotlin: меняет устойчивую предметную модель без пользовательской ценности;
- перенести SQLite-репозиторий: увеличивает риск регрессии и не улучшает демонстрацию interop;
- использовать `!!`: превращает явный договор в неуправляемый отказ;
- оставить только факт компиляции: не доказывает JVM-сигнатуру, null и наличие runtime в поставке.
