# Практика 19. Настройки, журналирование и диагностика

Самостоятельный Gradle-проект дневника питания КБЖУ. Практика отделяет изменяемые данные от каталога поставки: приложение читает внешний файл настроек, разрешает относительные пути от явного корня данных, проверяет конфигурацию до основной работы и пишет диагностические события без секретов и содержимого планов питания.

## Требования

- JDK 25 (проверено на 25.0.4);
- Gradle Wrapper 9.1;
- графический сеанс для JavaFX-проверок и запуска окна;
- Интернет нужен только для первоначального заполнения кэша Gradle.

## Основная проверка

Из каталога `Практика_19`:

```shell
./gradlew clean testDiagnostics runLessonDemo
```

Windows:

```text
gradlew.bat clean testDiagnostics runLessonDemo
```

`testDiagnostics` проверяет внешний файл, документированные значения по умолчанию, относительные и абсолютные пути, пустое и некорректное значение, подготовку каталогов, повторное открытие журнала и запрет чувствительных данных.

Полная регрессия самостоятельного проекта:

```shell
./gradlew clean check testDiagnostics runLessonDemo
```

## Внешняя конфигурация

Рабочий пример находится в [`config/application.properties`](config/application.properties):

```properties
database.path=data/nutrition-plans.db
log.directory=logs
backup.directory=backup
```

Корень данных задаётся системным свойством `kbju.data.dir`. При обычном запуске через Gradle используется `.lesson-data` текущей практики; код приложения по умолчанию выбирает `.kbju-diary` в профиле пользователя. Файл настроек выбирается свойством `kbju.config`, а через Gradle — параметром `-PkbjuConfig`.

Относительные значения `database.path`, `log.directory` и `backup.directory` всегда считаются от `kbju.data.dir`, а не от текущего каталога терминала. Абсолютный путь применяется как указан. Нормализация пути не считается проверкой прав доступа или границей безопасности.

Проверка отдельной учебной конфигурации:

```shell
./gradlew runLessonDemo \
  -PkbjuDataDir=/tmp/kbju-practice19 \
  -PkbjuConfig=docs/examples/application-custom.properties
```

Отсутствующий файл или отдельный необязательный ключ приводит к документированным значениям по умолчанию. Пустое значение, неверный путь и недоступный каталог дают ранний `AppConfigurationException` с именем ключа без публикации исходного значения.

## Безопасный журнал

`ApplicationLog` создаёт до трёх файлов по 256 Кбайт в настроенном каталоге. Событие содержит только стабильное имя, идентификатор, операцию, исход и код причины. Текст исключения и stack trace не записываются, потому что могут содержать токен, имя плана или другие личные данные.

Пример разделения сообщений:

- пользователю: `Не удалось сохранить план; проверьте доступ к каталогу данных и повторите. Код события: ...`;
- журналу: `event=operation_failed eventId=... operation=PLAN_SAVE reason=STORAGE_UNAVAILABLE`.

В журнал запрещено помещать пароли, токены, HTTP-заголовки авторизации, содержимое планов и измерений, полные тела запросов и ответов, а также произвольный `toString()` предметного объекта.

## Диагностика в три шага

1. Повторить действие и записать ожидаемый результат, фактический исход и код события.
2. Проверить имя проблемной настройки и разрешённые пути командой `runLessonDemo`, не открывая пользовательскую базу.
3. Передать только относящиеся к коду события строки журнала и версию приложения; базу, секреты и весь пользовательский каталог не отправлять.

## Запуск приложения

```shell
./gradlew run
./gradlew run --args="--smoke"
```

При ошибке конфигурации приложение показывает отдельный экран с дальнейшим действием и кодом события. Если каталог журнала уже доступен, технический отказ также получает связанную запись без текста чувствительного исключения.

Каталог резервных копий только настраивается и подготавливается. Создание и безопасное восстановление копии относятся к практике 20.
