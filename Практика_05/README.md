# Практика 05. Первое окно JavaFX и обработка событий

Самостоятельный проект на Java 25 и JavaFX 25 в предметной области дневника питания КБЖУ. Окно показывает таблицу планов питания текущего сеанса. Форма добавляет один новый черновик, а пустое название не меняет таблицу и приводит к понятному сообщению.

## Что реализовано

- одна исходная запись «Снижение массы»;
- таблица с идентификатором, названием, датой начала и состоянием;
- форма с предметной подсказкой;
- одно нажатие кнопки создаёт ровно одну строку;
- после успеха поле очищается и появляется подтверждение;
- пустой или пробельный ввод сохраняет прежнее число строк;
- контейнеры JavaFX сохраняют доступность элементов при изменении размера окна;
- модель не зависит от JavaFX;
- данные хранятся только в памяти процесса.

## Требования

- полный JDK 25;
- Linux, macOS или Windows с графической средой;
- доступ к Интернету при первой загрузке Gradle, JavaFX и JUnit.

Проверка среды:

```shell
java -version
javac -version
```

## Сборка и тесты

Из папки `Практика_05` выполните:

```shell
./gradlew clean check
```

Для Windows:

```text
gradlew.bat clean check
```

## Запуск окна

```shell
./gradlew run
```

Для Windows:

```text
gradlew.bat run
```

Точка входа: `src/main/java/ru/npi/kbju/Launcher.java`. Жизненный цикл окна реализован в `src/main/java/ru/npi/kbju/ui/DesktopApp.java`.

Короткая автоматическая проверка фактического показа окна завершается самостоятельно:

```shell
./gradlew run --args=--smoke
```

## Воспроизводимая проверка состояний интерфейса

Служебная задача запускает настоящее JavaFX-окно, выполняет успешный и ошибочный ввод, изменяет размер окна и сохраняет снимки в `docs/evidence`:

```shell
./gradlew captureEvidence
```

После первой загрузки зависимостей весь комплект проверяется без сети:

```shell
./gradlew --offline clean check captureEvidence
./gradlew --offline run --args=--smoke
```

## Контролируемый отказ

Введите только пробелы или оставьте поле пустым и нажмите «Добавить план». Таблица не изменится, приложение не завершится с ошибкой, а сообщение предложит ввести непустое название. Затем введите корректное название и повторите действие.

## Почему данные исчезают после закрытия

Текущий `NutritionPlanService` хранит записи в оперативной памяти JVM. Каждый новый запуск создаёт сервис заново с одной исходной записью. Постоянное хранилище появится в последующих практиках.

## Структура

- `domain/NutritionPlan.java` — предметная запись и инварианты из практики 03;
- `application/NutritionPlanService.java` — одна операция добавления в памяти процесса;
- `ui/NutritionPlanView.java` — таблица, форма и обработчик события;
- `ui/DesktopApp.java` — создание `Stage` и `Scene`;
- `docs/scene-graph.md` — фактический граф контейнеров;
- `docs/decision.md` — причинная связь и ограничения;
- `docs/check-protocol.md` — ожидаемые и фактические результаты;
- `docs/evidence/` — выводы команд и снимки JavaFX.

Практика не использует FXML, CSS, базу данных, HTTP или существующий TypeScript-backend.
