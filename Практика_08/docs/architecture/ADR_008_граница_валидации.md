# ADR 008. Граница проверки ввода

- Статус: принято
- Дата: 2026-10-01

## Контекст

Пользователь должен исправлять неверный ввод без перезапуска и повторного заполнения формы. Одновременно предметная запись обязана оставаться корректной при создании вне JavaFX.

## Решение

Разделить обязанности:

- FXML описывает поля, постоянные подписи и места для текстов ошибок;
- `MainController` проверяет наличие и формат, ловит только ожидаемые типы и управляет фокусом;
- `NutritionPlan` повторно проверяет инварианты и сообщает `PlanValidationException.Field`;
- `NutritionPlanService` сообщает ожидаемый конфликт уникальности через checked `DuplicatePlanException`;
- CSS оформляет семантический `:invalid`, но текст остаётся обязательным носителем смысла.

Контроллер не очищает поля при отказе. Сервис сначала создаёт допустимый объект и проверяет уникальность, только затем меняет наблюдаемый список и следующий ID.

## Последствия

- одна ошибка указывает на одно исправляемое поле;
- неверный ввод не достигает списка;
- программные дефекты не маскируются общим перехватом;
- UI и модель проверяются отдельно и совместно;
- структура ещё не является полной слоистой архитектурой — это задача практики 09.
