# Практика 08. Проверка ввода, исключения и доступность

Самостоятельный Gradle-проект дневника питания КБЖУ. Некорректный ввод не меняет таблицу, форма объясняет способ исправления, сохраняет черновик пользователя и полностью проходится клавиатурой.

## Требования

- JDK 25 (проверено на 25.0.4);
- Linux, macOS или Windows с графической средой;
- Интернет при первом разрешении Gradle 9.1 и JavaFX 25; повторные команды работают из подготовленного кэша.

## Сборка и запуск

Из каталога `Практика_08`:

```shell
./gradlew clean check
./gradlew run
```

Windows:

```text
gradlew.bat clean check
gradlew.bat run
```

Точка входа — `ru.npi.kbju.Launcher`. FXML и CSS загружаются из classpath. Для запуска проверочного JavaFX-сценария со снимками:

```shell
./gradlew captureEvidence
```

Короткий запуск окна, печать фактов загрузки и автоматическое закрытие:

```shell
./gradlew run --args="--smoke"
```

После подготовки кэша автономная проверка выполняется так:

```shell
./gradlew --offline clean check
./gradlew --offline run --args="--smoke"
```

## Что проверить вручную

1. Открыть приложение: фокус сразу находится в поле названия.
2. Ввести только пробелы и нажать Enter: строка не появляется, возле названия есть текст ошибки, остальные поля сохранены.
3. Ввести название и дату `2026-13-40`: строка не появляется, дата остаётся в поле, сообщение содержит формат и пример.
4. Исправить только дату на `2026-11-01` и повторить: план сохраняется без перезапуска и ровно один раз.
5. Попробовать то же название в другом регистре: checked-исключение дубликата превращается в понятное сообщение возле названия.
6. Закрыть и открыть окно; без мыши пройти `название → Tab → дата → Tab → состояние → Tab → Сохранить → Enter`. `Shift+Tab` возвращает фокус назад.

Красная рамка дублируется текстом, поэтому цвет не является единственным носителем ошибки. После любого отказа кнопка остаётся доступной для повторной попытки.

## Границы обработки ошибок

- Пустое и слишком длинное название проверяются формой для быстрой обратной связи и повторно моделью `NutritionPlan`.
- Текст даты разбирается только на границе UI; контроллер ловит конкретно `DateTimeParseException`.
- Повтор названия сообщает сервис через checked `DuplicatePlanException`; контроллер обрабатывает именно этот тип.
- Инварианты модели сообщаются через `PlanValidationException` с именем проблемного поля.
- Общих `catch (Exception)` и `catch (Throwable)` в рабочем коде нет; неожиданные дефекты не маскируются.
