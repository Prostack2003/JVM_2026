# Практика 04. Коллекции и типобезопасный счётчик обращений

Самостоятельный проект на Java 25 в предметной области дневника питания КБЖУ. Универсальный `CountMap<T>` считает повторные обращения по предметному ключу. В демонстрационном маршруте ключом служит строковый код продукта, например `FOOD-101`.

## Предметный результат

Первый набор содержит два обращения к `FOOD-101` и одно к `FOOD-102`. Второй набор добавляет одно обращение к `FOOD-101` и два к `FOOD-103`. После объединения ожидаются количества `3`, `1` и `2`; второй счётчик остаётся неизменным.

`toMap()` возвращает отдельный неизменяемый снимок. Его нельзя изменить, а последующие операции исходного счётчика не влияют на ранее полученную карту.

## Требования

- полный JDK 25;
- Linux, macOS или Windows с терминалом;
- доступ к Интернету при первой загрузке Gradle и JUnit.

Проверка среды:

```shell
java -version
javac -version
```

## Сборка, тесты и запуск

Из папки `Практика_04` выполните:

```shell
./gradlew clean check run
```

Для Windows:

```text
gradlew.bat clean check run
```

После первой успешной загрузки зависимостей проверка выполняется без сети:

```shell
./gradlew --offline clean check run
```

## Контролируемые отказы

`null` запрещён как ключ, источник объединения и карта-приёмник. Такие вызовы завершаются `NullPointerException` до изменения внутреннего состояния.

Попытка выполнить `put` для результата `toMap()` завершается `UnsupportedOperationException`. Это ожидаемый отказ: вызывающий код не может менять количества в обход `add`, `remove` и `addAll`.

## Структура

- `src/main/java/ru/npi/kbju/collection/CountMap.java` — универсальный счётчик и контракты методов;
- `src/main/java/ru/npi/kbju/Practice04App.java` — предметный консольный маршрут;
- `src/test/java/ru/npi/kbju/collection/CountMapTest.java` — двенадцать JUnit-проверок;
- `docs/prediction.md` — прогноз результата и сравнение коллекций;
- `docs/contract.md` — контракт методов, `null` и границы ответственности;
- `docs/decision.md` — обоснование `Map`, снимка, `TreeMap` и PECS;
- `docs/check-protocol.md` — ожидаемые и фактические результаты;
- `docs/evidence/` — выводы проверочных запусков.

На этом этапе проект не использует JavaFX, базу данных, HTTP или существующий TypeScript-backend.
