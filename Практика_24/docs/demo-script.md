# Сценарий семиминутной защиты

## 0:00–0:45. Пользователь и задача

Пользователь локально управляет планами питания. Ценность выпуска — воспроизводимое сохранение и понятное поведение при отказах без зависимости от облачного backend.

## 0:45–2:15. Основной маршрут

Открыть app-image, добавить план `Приёмка 24`, дату `2026-10-24` и состояние `Черновик`. Показать новую строку и сообщение о сохранении.

## 2:15–3:00. Отрицательный ввод

Ввести пробелы вместо названия. Показать точную ошибку и неизменное число строк.

## 3:00–3:45. Перезапуск

Закрыть и снова запустить приложение с тем же каталогом данных. Найти `Приёмка 24` в таблице. Связать результат с SQLite-адаптером и `verifyPackagedLaunch`.

## 3:45–4:45. Недоступный сервис

Показать сокращённый вывод `runOfflineCatalogAcceptance`: допустимый кэш используется после двух попыток, отсутствие или повреждение кэша даёт точный отказ.

## 4:45–5:45. Восстановление

Показать `runBackupRecoveryAcceptance`: integrity равен `ok`, копия восстановлена только в новый путь, повреждённый файл отклонён, рабочая база не изменилась.

## 5:45–6:30. Архитектурное решение

Объяснить направление UI → application → domain port ← infrastructure. Назвать узкий Kotlin-форматировщик и причину, по которой UI, SQLite и предметные правила остались на Java.

## 6:30–7:00. Доказательства и ограничения

Открыть матрицу, паспорт и SHA-256. Назвать подтверждённую платформу Linux/amd64 и непройденную человеческую передачу. Перечислить функции широкого исходного замысла, которые не заявлены в текущем выпуске.
