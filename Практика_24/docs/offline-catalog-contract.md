# Контракт кэша и автономной работы

## Последовательность загрузки

1. `ResilientProductCatalogService` запрещает второе параллельное обновление.
2. Фоновый executor вызывает HTTP-порт `ProductDirectory`.
3. HTTP-адапт проверяет статус, тип, размер и JSON-контракт.
4. При успехе сервис фиксирует `Clock.instant()` и передаёт весь снимок в `ProductCatalogCache`.
5. `FileProductCatalogCache` пишет JSON во временный файл в том же каталоге и затем заменяет прежнюю копию через `ATOMIC_MOVE`. Если файловая система не поддерживает атомарное перемещение, используется `REPLACE_EXISTING` после полной записи временной копии.
6. Возвращается `CatalogSnapshot` с источником `NETWORK`, временем и нулевым возрастом.

Кэш не хранит секреты, авторизацию или личные записи питания. В нём находится только общий справочник продуктов и `receivedAt`.

## Retry и fallback

| Отказ | Retry | Кэш | Причина |
|---|---:|---:|---|
| таймаут | да | да | временная недоступность |
| транспорт | да | да | сервер недоступен |
| HTTP 429 | да | да | временное ограничение частоты; учебная версия не разбирает `Retry-After` |
| HTTP 5xx | да | да | временный отказ сервера |
| HTTP 401/403 | нет | нет | кэш не должен скрывать отзыв доступа |
| другой HTTP 4xx | нет | нет | нужно исправить запрос или контракт |
| повреждённый JSON | нет | нет | нарушение внешнего контракта должно быть видно |
| недопустимый продукт | нет | нет | данные не подтверждены |
| interrupt | нет | нет | отмена не превращается в успех |

Предел — 2 попытки включая первую, пауза — 100 мс. GET идемпотентен по контракту практики. Для POST эта политика не применима без ключа идемпотентности и поддержки сервера.

## Состояния кэша

| Состояние | Результат |
|---|---|
| возраст от 0 до 24 ч включительно | `Source.CACHE`, показаны `receivedAt`, `age` и причина fallback |
| старше 24 ч | `EXPIRED_CACHE` |
| `receivedAt` в будущем | `CLOCK_ROLLBACK` |
| файла нет | `NO_SAVED_DATA`, действие «Повторить запрос» |
| JSON кэша повреждён | `CORRUPT_CACHE`; данные не показываются |
| файл не читается | `CACHE_READ_FAILED` |

`Clock` передаётся в сервис, поэтому границы воспроизводятся без ожидания реальных суток.

## Ограничения

- Кэш не является источником новых изменений справочника.
- Автономные данные не выдаются за синхронизированные.
- Одновременно может выполняться только один `refreshAsync`.
- Каталог кэша должен находиться в доступном для записи каталоге данных приложения.
