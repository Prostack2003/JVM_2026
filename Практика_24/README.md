# Практика 24. Итоговая приёмка и защита проекта

Самостоятельный Gradle-проект финального учебного выпуска «Дневник питания КБЖУ» версии `24.0.0`. Практика связывает пять сценариев текущей границы продукта с кодом, автоматическими проверками, запуском app-image и документами выпуска.

## Решение о границе выпуска

Текущий продукт управляет локальными планами питания: создаёт их, проверяет ввод, меняет состояние, сохраняет в SQLite, выполняет аудит, работает с автономным каталогом и поддерживает проверенное резервное копирование. Более широкое направление из практики 1 — профиль, полноценный дневник приёмов пищи, история веса и дневные суммы КБЖУ — не выдаётся за реализованное. Причина и последствия зафиксированы в [изменении требований](docs/requirements-change.md) и [известных ограничениях](docs/known-limitations.md).

## Требования

- JDK 25, проверено на `25.0.4.1`;
- Gradle Wrapper 9.1;
- подготовленный кэш зависимостей для автономного запуска;
- Linux, Windows или macOS для обычной сборки;
- `jpackage` создаёт app-image только для текущей ОС и архитектуры.

Проверка среды:

```shell
java -version
javac -version
./gradlew --version
```

## Быстрая приёмка

Из каталога `Практика_24`:

```shell
./gradlew --offline clean releaseAcceptance
```

Команда выполняет накопительную регрессию, демонстрацию отказа локального сервиса, восстановление SQLite в новый временный путь, проверку app-image и сборку финального архива.

Для короткой проверки без пересборки app-image:

```shell
./gradlew --offline clean check verifyReleaseDocumentation
```

## Пять сценариев выпуска

| Код | Наблюдаемый результат | Основное доказательство |
|---|---|---|
| ПР-01 | План добавляется через реальный FXML-интерфейс | `JavaFxUserJourneyTest` |
| ПР-02 | Пустое название отклоняется без изменения данных | `JavaFxUserJourneyTest` |
| ПР-03 | Запись видна после повторного запуска app-image | `verifyPackagedLaunch` |
| ПР-04 | При недоступном локальном сервисе используется допустимый кэш либо выдаётся точный отказ | `runOfflineCatalogAcceptance` |
| ПР-05 | Проверенная копия SQLite восстанавливается только в новый тестовый файл | `runBackupRecoveryAcceptance` |

Полные связи требования, кода, теста, команды и файла находятся в [матрице прослеживаемости](docs/traceability-matrix.md).

## Исправленный дефект

В практике 23 начальное сообщение аудита содержало обрезанное слово `результ`. В выпуске исправлены начальное сообщение и сообщение отмены. Тест `initialAuditMessageUsesCompleteWord` защищает пользовательский текст от регрессии. Подробности приведены в [карточке дефекта](docs/defect-report.md).

## Запуск приложения

```shell
./gradlew --offline run
```

Smoke-проверка:

```shell
./gradlew --offline run --args="--smoke"
```

Проверенный app-image после `releaseAcceptance`:

```text
build/package/KbjuDiary/
```

На Linux launcher расположен в `build/package/KbjuDiary/bin/KbjuDiary`.

## Выпуск

`verifyDistribution` создаёт архив app-image и SHA-256. `verifyReleaseBundle` дополнительно создаёт финальный архив с приложением, исходниками, документацией и доказательствами:

```text
build/distributions/KbjuDiary-24.0.0-release-bundle-<os>-<arch>.tar.gz
build/distributions/KbjuDiary-24.0.0-release-bundle-<os>-<arch>.tar.gz.sha256
```

Собранные архивы не хранятся в Git и воспроизводятся из исходников.
