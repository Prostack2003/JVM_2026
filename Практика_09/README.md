# Практика 09. Слои приложения и замена хранилища

Самостоятельный Gradle-проект дневника питания КБЖУ. Контроллер вызывает прикладной сервис, сервис работает только через `NutritionPlanRepository`, а конкретное хранилище в памяти подключается в точке сборки приложения.

## Требования

- JDK 25 (проверено на 25.0.4);
- Linux, macOS или Windows с графической средой;
- Интернет только для первой загрузки Gradle 9.1 и JavaFX 25; затем команды выполняются из кэша.

## Сборка и запуск

Из каталога `Практика_09`:

```shell
./gradlew clean check
./gradlew run
```

Windows:

```text
gradlew.bat clean check
gradlew.bat run
```

Точка входа — `ru.npi.kbju.Launcher`. Короткий фактический запуск JavaFX с автоматическим закрытием:

```shell
./gradlew run --args="--smoke"
```

Прикладные сценарии без запуска окна:

```shell
./gradlew testService
```

Проверочный JavaFX-сценарий со снимками, включая сортировку и сохранение выбора по ID:

```shell
./gradlew captureEvidence
```

После подготовки кэша автономная проверка:

```shell
./gradlew --offline clean check testService
./gradlew --offline run --args="--smoke"
```

## Как устроена цепочка

1. `MainController` разбирает поля и передаёт значения в `NutritionPlanService`.
2. Сервис выполняет сценарий и обращается к интерфейсу `NutritionPlanRepository`.
3. `MemoryNutritionPlanRepository` реализует интерфейс и владеет изменяемой коллекцией.
4. `ApplicationContext` — единственное место, где выбирается конкретный адаптер и создаётся сервис.

Интерфейс нужен не «для каждого класса», а на реальной границе замены: сервис одинаково работает с новым экземпляром памяти, тестовым двойником или будущей базой данных. В `domain` и `application` нет импортов JavaFX; контроллер не импортирует `infrastructure`.

## Ручная приёмка

1. Создать план: в таблице появляется запись с новым ID.
2. Повторить название в другом регистре: появляется понятный отказ, число строк не меняется.
3. Отсортировать таблицу по названию, выбрать строку и изменить состояние: выбранным остаётся тот же ID.
4. Выполнить `testService`: сценарии проходят без открытия окна JavaFX.

Состояние хранится только в памяти текущего контекста. Два новых репозитория независимы; SQL, HTTP и постоянное хранение намеренно не добавлены.
