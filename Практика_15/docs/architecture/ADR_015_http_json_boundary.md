# ADR 015: HTTP и JSON остаются за портом каталога

## Статус

Принято для практики 15.

## Контекст

Приложению нужен внешний справочник продуктов. HTTP-статус, JSON и Jackson — детали интеграции, а не часть предметной модели. Сетевой ответ нельзя публиковать частично: одна плохая запись должна отклонить весь кандидат.

## Решение

- Прикладной порт `ProductDirectory` возвращает только `List<FoodProduct>`.
- `HttpProductDirectory` владеет `HttpClient`, URI, таймаутами и проверкой HTTP-оболочки.
- `FoodProductJsonMapper` разбирает дерево, проверяет весь кандидат и лишь затем создаёт неизменяемый список.
- `ProductCatalogRefreshService` сам не создаёт поток: он получает `Executor` от владельца жизненного цикла и запускает `fetch()` фоново.
- Подтверждённый снимок заменяется одним `AtomicReference.set` только после полной проверки.
- Внешние классы видят типизированную `DirectoryLoadException`, но не исключения Jackson.

## Последствия

Предметный и прикладной код не зависят от HTTP и JSON. Адаптер можно проверить на локальном сервере без Интернета. Ошибка одной записи не оставляет полукаталог. Владелец executor и учебного сервера обязан закрыть их.

Кэш, retry и offline-fallback остаются отдельным решением следующей практики.
