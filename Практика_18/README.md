# Практика 18. Интеграционные и интерфейсные проверки

Самостоятельный Gradle-проект дневника питания КБЖУ. Практика собирает регрессионный портфель по рискам: предметные правила проверяются без UI, SQLite — на отдельных временных файлах, FXML — как classpath-ресурс, а критический пользовательский путь — через реальные JavaFX-элементы.

## Требования

- JDK 25 (проверено на 25.0.4);
- Gradle Wrapper 9.1;
- графический сеанс для JavaFX-теста и ручного запуска;
- Интернет нужен только для первой загрузки зависимостей.

## Полная проверка

Из каталога `Практика_18`:

```shell
./gradlew clean check
```

Windows:

```text
gradlew.bat clean check
```

Команда компилирует проект, выполняет весь JUnit-набор и проверяет обязательные ресурсы в JAR. HTML-отчёт: `build/reports/tests/test/index.html`; результаты сгруппированы по пакетам `domain`, `application`, `infrastructure`, `integration` и `ui`.

Фокус практики можно повторить отдельно:

```shell
./gradlew clean testIntegrationAndUi
```

Отчёт профильного запуска: `build/reports/tests/testIntegrationAndUi/index.html`.

## Что доказывают уровни

| Уровень | Риск | Доказательство |
|---|---|---|
| domain | нарушен инвариант плана | `NutritionPlanTest` |
| application | сервис неверно координирует сценарий | тесты прикладных сервисов |
| infrastructure | JDBC, миграция или ограничение SQLite работают неверно | `SqliteNutritionPlanRepositoryTest` и отдельный `@TempDir` |
| integration | нарушен HTTP/JSON/кэш-контракт | loopback-сервер и временные файлы |
| ui resource | FXML не упакован или потерял связь с контроллером | `FxmlResourceTest` |
| ui journey | ввод не проходит через кнопку в таблицу и репозиторий | `JavaFxUserJourneyTest` |

Положительный JavaFX-сценарий вводит название, дату и состояние, нажимает настоящую кнопку из FXML и сверяет таблицу, сообщение и содержимое репозитория. Отрицательный сценарий вводит пробелы вместо названия и подтверждает видимую полевую ошибку без сохранения. Все операции со сценой выполняются в FX Application Thread, а завершение ожидается через `CountDownLatch`; фиксированного `sleep` нет.

SQLite-проверка создаёт собственную временную базу, записывает план, закрывает соединение, повторно открывает файл и сверяет все значения. Пользовательская `.lesson-data` не используется.

## Ручная проверка окна

```shell
./gradlew run
```

Проверить:

1. Ввести название, дату и состояние, нажать «Сохранить план», увидеть новую строку и сообщение.
2. Ввести пробелы вместо названия, увидеть полевую ошибку и сохранённый черновик других полей.
3. Пройти форму клавишами `Tab`, `Shift+Tab` и `Enter`.
4. Изменить размер окна и убедиться, что форма не перекрывает таблицу.

Автоматический JavaFX-тест подтверждает связь FXML, контроллера и сервиса в текущей среде. Он не подтверждает внешний вид шрифтов, контраст, системное масштабирование, работу экранного диктора или установку на другой ОС, поэтому эти свойства требуют отдельного ручного прогона.

## Автономное воспроизведение

После подготовки кэша:

```shell
./gradlew --offline clean check
./gradlew --offline run --args="--smoke"
```

Локальные данные окна хранятся в `.lesson-data` и исключены из Git.
