# Практика 13. Фоновая задача и отмена операции

Самостоятельный Gradle-проект дневника питания КБЖУ. Длительный аудит планов выполняется в `JavaFX Task`, показывает прогресс и позволяет отменить работу без зависания окна.

## Требования

- JDK 25 (проверено на 25.0.4);
- Linux, macOS или Windows с графической средой;
- Интернет только при первой загрузке Gradle 9.1, JavaFX 25 и SQLite JDBC.

## Сборка и запуск

Из каталога `Практика_13`:

```shell
./gradlew clean check testBackground
./gradlew run
```

Windows:

```text
gradlew.bat clean check testBackground
gradlew.bat run
```

Точка входа — `ru.npi.kbju.Launcher`. Короткий запуск окна с автозакрытием:

```shell
./gradlew run --args="--smoke"
```

После первой загрузки зависимостей:

```shell
./gradlew --offline clean check testBackground
./gradlew --offline run --args="--smoke"
```

## Сценарий приёмки в окне

1. Нажать **Начать аудит**. Индикатор и текст этапа меняются, а окно можно перемещать и масштабировать.
2. Дождаться успеха: прогресс равен 100 %, а итог помечен как подтверждённый.
3. Запустить ещё раз и нажать **Отменить**. Неполный итог не публикуется; прежний подтверждённый итог остаётся.
4. Включить **Учебный отказ на 4-м шаге** и запустить аудит. Причина отказа показывается, данные и последний подтверждённый итог не меняются.
5. Выключить учебный отказ и повторить запуск. Создаётся новый экземпляр `Task`, он завершается успешно.

Автоматизированный вариант этого маршрута сохраняет снимки:

```shell
./gradlew captureAuditEvidence
```

## Контракт фоновой операции

- `MainController` берёт `List.copyOf(visiblePlans)` и для каждого запуска создаёт новую `NutritionPlanAuditTask`.
- `Task.call()` работает в отдельном виртуальном потоке, не знает о `Label`, `ProgressBar` и `TableView`.
- Прогресс и сообщение передаются через `updateProgress` и `updateMessage`.
- Отмена — это запрос. Аудитор проверяет его до и после каждой короткой порции.
- `AuditResult` публикуется только после всех проверок. Отмена или ошибка не заменяют ею последний достоверный итог.
- Обработчики `SUCCEEDED`, `CANCELLED` и `FAILED` снимают привязки и возвращают кнопки в согласованное состояние.

Учебный флажок отказа нужен только для воспроизводимой проверки `FAILED`; он не изменяет SQLite.
