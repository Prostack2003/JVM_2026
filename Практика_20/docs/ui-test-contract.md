# Контракт интерфейсной проверки

## Проверяемая цепочка

`main-view.fxml → MainController → NutritionPlanService → MemoryNutritionPlanRepository → TableView/Label`

`JavaFxUserJourneyTest` загружает тот же FXML, что и приложение, находит элементы по устойчивым `fx:id`, вводит данные и вызывает `Button.fire()`. Успешный результат читается из таблицы, сообщения и репозитория. Ошибка обработчика или потерянная связь `onAction` не дают ожидаемой строке появиться и делают тест красным.

## Синхронизация

Инициализация JavaFX и каждое действие сцены завершаются через `CountDownLatch` с пределом восемь секунд. Тест не использует фиксированную паузу и не читает узлы вне FX Application Thread.

## Изоляция

Каждый сценарий создаёт новый `MemoryNutritionPlanRepository`; порядок тестов не влияет на идентификаторы и данные. Настоящая SQLite проверяется отдельным интеграционным тестом с `@TempDir`, чтобы сбой SQL не маскировался ошибкой интерфейса.

## Честная граница вывода

Автоматическая проверка подтверждает соединение разметки, обработчика, сервиса и наблюдаемого результата в текущем графическом сеансе. Она не оценивает шрифты, контраст, системное масштабирование, экранный диктор, физический ввод мышью и установку на другую ОС.
