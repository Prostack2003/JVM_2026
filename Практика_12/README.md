# Практика 12. Транзакции, миграции и импорт CSV

Самостоятельный Gradle-проект дневника питания КБЖУ. Проект развивает SQLite-хранилище из практики 11: схема обновляется до V002 один раз, а пакет планов из CSV сохраняется целиком либо полностью откатывается.

## Требования

- JDK 25 (проверено на 25.0.4);
- Linux, macOS или Windows с графической средой;
- Интернет только при первой загрузке Gradle 9.1, JavaFX 25 и SQLite JDBC.

## Сборка и приёмка

Из каталога `Практика_12`:

```shell
./gradlew clean check testTransactions runLessonDemo
./gradlew run
```

Windows:

```text
gradlew.bat clean check testTransactions runLessonDemo
gradlew.bat run
```

Точка входа JavaFX-приложения — `ru.npi.kbju.Launcher`. Консольная воспроизводимая приёмка транзакций и миграций — `ru.npi.kbju.lesson.TransactionDemo`.

Короткая проверка реального окна с автозакрытием:

```shell
./gradlew run --args="--smoke"
```

Регрессионный UI-сценарий со снимками:

```shell
./gradlew captureEvidence
```

После первой загрузки зависимостей проект проверяется без сети:

```shell
./gradlew --offline clean check testTransactions runLessonDemo
./gradlew --offline run --args="--smoke"
```

## Формат CSV

Файл кодируется в UTF-8, разделитель — `;`, заголовок должен точно совпадать:

```csv
code;name;effective_from
KBJU-101;Баланс на неделю;2026-11-01
```

- `code` — 2–24 символа `A–Z`, `0–9`, `_` или `-`; код нормализуется в верхний регистр;
- `name` подчиняется инвариантам `NutritionPlan`;
- `effective_from` — строгая ISO-дата `yyyy-MM-dd`;
- кавычки, экранирование разделителя и многострочные поля в учебном формате не поддерживаются.

Готовые наборы лежат в `src/main/resources/ru/npi/kbju/lesson/import/`: `plans-valid.csv` добавляет две строки, `plans-duplicate-code.csv` вызывает откат всего пакета.

## Транзакционный контракт

1. Парсер читает и проверяет весь CSV до обращения к репозиторию.
2. Репозиторий отключает `autoCommit`, вставляет все строки одним соединением и вызывает `commit` только после последней строки.
3. Любая ошибка SQLite вызывает `rollback`; `BatchImportException` сохраняет проблемный код и первичную причину.
4. Исходный режим `autoCommit` восстанавливается; ошибка самого отката не теряется.

V001 осталась неизменной. V002 добавляет нулевой `import_code` и уникальный частичный индекс. Поэтому старые ручные записи из практики 11 сохраняются с `NULL`, а коды новых импортов защищены от дублей. История хранится в `schema_migration`; каждая версия выполняется один раз и в порядке номеров.

## Данные и границы

При `./gradlew run` база лежит в `Практика_12/.lesson-data/nutrition-plans.db`; каталог исключён из Git. При обычном запуске вне Gradle используется `${user.home}/.kbju-diary/nutrition-plans.db`; путь можно заменить системным свойством `kbju.data.dir`. Абсолютных путей в исходниках нет.

Импорт проверяется через консольную приёмку и JUnit; новый экран импорта и фоновое выполнение не добавляются: это граница следующих этапов.
