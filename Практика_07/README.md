# Практика 07. Разметка FXML и оформление формы

Самостоятельный проект на Java 25 и JavaFX 25 в предметной области дневника питания КБЖУ. Композиция экрана вынесена в FXML, визуальное оформление — в CSS, а обработчики действий находятся в контроллере с внедрённым прикладным сервисом.

## Что реализовано

- `main-view.fxml` описывает таблицу, три поля формы и действия;
- `style.css` содержит только семантическое визуальное оформление;
- `MainController` связывает `fx:id`, настраивает таблицу и переводит события в вызовы сервиса;
- `FXMLLoader` получает контроллер через `controllerFactory`, поэтому сервис передаётся конструктором;
- FXML и CSS загружаются через `Class.getResource` из classpath, без путей к рабочему каталогу;
- форма содержит название, дату начала и состояние плана;
- подписи программно связаны со своими полями, а порядок полей совпадает с визуальным порядком;
- таблица растёт вместе с окном, форма имеет минимальную ширину и не перекрывает таблицу;
- намеренно повреждённая временная копия FXML воспроизводит ошибку несвязанного `fx:id`;
- собранный JAR автоматически проверяется на наличие обоих ресурсов.

## Требования

- полный JDK 25;
- Linux, macOS или Windows с графической средой;
- доступ к Интернету при первой загрузке Gradle, JavaFX и JUnit.

Проверка среды:

```shell
java -version
javac -version
```

## Сборка и тесты

Из папки `Практика_07` выполните:

```shell
./gradlew clean check
```

Для Windows:

```text
gradlew.bat clean check
```

Задача `check` запускает JUnit и `verifyPackagedResources`. Последняя открывает собранный JAR и проверяет наличие:

- `ru/npi/kbju/ui/main-view.fxml`;
- `ru/npi/kbju/ui/style.css`.

## Запуск окна

```shell
./gradlew run
```

Для Windows:

```text
gradlew.bat run
```

Точка входа: `src/main/java/ru/npi/kbju/Launcher.java`. Загрузка ресурсов и создание сцены находятся в `src/main/java/ru/npi/kbju/ui/DesktopApp.java`.

Короткий фактический запуск самостоятельно закрывает окно и печатает результаты classpath-загрузки:

```shell
./gradlew run --args=--smoke
```

## Воспроизводимая проверка интерфейса

```shell
./gradlew captureEvidence
```

Задача запускает настоящее JavaFX-окно и проверяет:

1. связывание трёх полей FXML и подключение CSS;
2. сохранение названия, даты и состояния;
3. компоновку при компактном и расширенном размере;
4. контролируемый отказ на копии FXML с `nameField`, переименованным в `brokenNameField`.

Рабочий FXML в отрицательном сценарии не изменяется. Временная копия удаляется после проверки. Снимки сохраняются в `docs/evidence`.

После первой загрузки зависимостей полный комплект проверяется без сети:

```shell
./gradlew --offline clean check captureEvidence
./gradlew --offline run --args=--smoke
```

## Ручной сценарий

1. Запустите приложение и убедитесь, что показана одна строка и `Планов: 1`.
2. Введите `Поддержание массы`, выберите дату `01.11.2026` и состояние `Действует`.
3. Нажмите `Сохранить план`: в таблице должна появиться строка со всеми тремя значениями, счётчик станет равен двум.
4. Уменьшите окно до минимального размера: форма остаётся справа и не перекрывает таблицу.
5. Увеличьте окно: свободное место получает таблица, ширина формы остаётся ограниченной.

## Почему `src/main/resources` не годится в поставке

Это путь каталога исходников, которого может не быть рядом с установленным приложением. Gradle помещает ресурсы внутрь JAR, поэтому приложение запрашивает абсолютные classpath-пути `/ru/npi/kbju/ui/main-view.fxml` и `/ru/npi/kbju/ui/style.css` через класс `DesktopApp`. Отсутствующий ресурс приводит к раннему отказу с сообщением, содержащим точный путь.

## Структура

- `domain/NutritionPlan.java` — неизменяемая предметная запись;
- `application/NutritionPlanService.java` — операции и наблюдаемый список;
- `ui/DesktopApp.java` — classpath-загрузка FXML/CSS и создание окна;
- `ui/MainController.java` — связывание элементов и обработчики;
- `resources/ru/npi/kbju/ui/main-view.fxml` — структура экрана;
- `resources/ru/npi/kbju/ui/style.css` — оформление;
- `docs/field-map.md` — таблица соответствия полей;
- `docs/decision.md` — объяснение границ решения;
- `docs/check-protocol.md` — ожидаемые и фактические результаты;
- `docs/evidence/` — выводы команд и снимки JavaFX.

Полная проверка ввода, сообщения рядом с каждым неверным полем и состояния ошибок относятся к практике 08. Эта практика не использует базу данных, файлы данных, HTTP или существующий TypeScript-backend.
