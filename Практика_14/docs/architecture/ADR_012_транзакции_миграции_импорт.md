# ADR 012: атомарный импорт и последовательные миграции

Статус: принято.

## Контекст

Практика 11 создавала только V001 и записывала по одному плану. Новый этап должен безопасно обновлять уже существующий файл и импортировать пакет так, чтобы ошибка в конце не оставляла частичные данные.

## Решение

- не изменять опубликованную V001; добавить V002;
- хранить факт применения версии в той же SQLite-базе;
- выполнять каждую миграцию и запись в журнал одной транзакцией;
- ввести отдельный порт `NutritionPlanBatchRepository`, не расширяя CRUD-порт обязанностями CSV;
- разобрать весь файл до транзакции, затем сохранить весь список на одном `Connection`;
- добавить нулевой `import_code`: так старые CRUD-строки совместимы, а новые импорты имеют устойчивый уникальный код.

## Следствия

Успешный импорт атомарен, а отказ указывает проблемный код и не меняет число строк. Старые базы обновляются при открытии; повторное открытие ничего не переприменяет. Упрощённый CSV не поддерживает кавычки и многострочные поля; ограничение явно описано и диагностируется.

Импорт пока не выведен в JavaFX и не выполняется в фоне: эти изменения не нужны для приёмки практики 12 и не предвосхищают практику 13.
