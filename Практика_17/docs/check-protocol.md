# Протокол проверки практики 17

Дата проверки: 3 октября 2026 года.

## Среда

- OpenJDK и `javac` 25.0.4;
- Gradle Wrapper 9.1.0;
- Linux 7.0.0-31-generic amd64.

## Целевой профиль

Команда:

```shell
./gradlew clean testDomainRules
```

Фактический результат: 15 запусков, 0 отказов. Профиль проверил обычную допустимую запись, отдельную границу `id=0`, шесть вариантов пустого имени, обе стороны границы длины, отрицательный ID, обязательные дату и статус, успешный и недопустимый `withStatus`. HTML-отчёт сформирован в `build/reports/tests/testDomainRules/index.html`.

## Мутационный эксперимент

Временное ослабление проверки пустого имени завершило профиль кодом 1: 15 запусков, 5 отказов в `rejectsEveryBlankNameVariant`. Параметр `null` сохранил ожидаемый отказ, а пустая строка, пробелы, табуляция и перевод строки выявили дефект. После фиксации вывода условие `isBlank()` возвращено. Два последовательных `clean testDomainRules` прошли по 15 запусков каждый.

## Полная регрессия

```shell
./gradlew clean check testDomainRules
```

Фактический результат: 120 основных запусков и 15 профильных, 0 отказов. FXML, CSS, миграции V001–V002 и CSV-ресурсы присутствуют в JAR. Обычный smoke-запуск загрузил интерфейсные ресурсы и одну строку SQLite.

## Автономное воспроизведение

```shell
./gradlew --offline clean check testDomainRules
./gradlew --offline run --args="--smoke"
```

Обе команды выполнены без обращения к внешним репозиториям. Автономная регрессия повторила 120 + 15 успешных запусков, а smoke-сценарий загрузил ту же базу с одной строкой.
