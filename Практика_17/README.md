# Практика 17. JUnit: правила предметной области

Самостоятельный Gradle-проект дневника питания КБЖУ. Практика доказывает правила `NutritionPlan` модульными JUnit-тестами: допустимую запись, границы входных данных, диагностируемые отказы и неизменяемую смену состояния.

## Требования

- JDK 25 (проверено на 25.0.4);
- Gradle Wrapper 9.1;
- Интернет нужен только для первой загрузки сборочных зависимостей.

## Основная проверка

Из каталога `Практика_17`:

```shell
./gradlew clean testDomainRules
```

Windows:

```text
gradlew.bat clean testDomainRules
```

Профиль запускает только `ru.npi.kbju.domain.NutritionPlanTest`. HTML-отчёт появляется в `build/reports/tests/testDomainRules/index.html`.

Полная регрессия самостоятельного проекта:

```shell
./gradlew clean check testDomainRules
```

## Что проверяется

- нулевой ID допустим, отрицательный отклоняется;
- имя нормализуется, но `null`, пустая строка и пробельные варианты запрещены;
- ровно 60 символов допустимы, 61 символ отклоняется;
- дата начала и статус обязательны;
- `withStatus` создаёт новый record, сохраняет остальные компоненты и не меняет исходный;
- недопустимый `withStatus(null)` не создаёт повреждённое состояние.

Все сценарии используют фиксированную дату и собственные фикстуры. Они не зависят от порядка, текущих часов, JavaFX, SQLite или сети.

## Проверка мутацией

Для контроля полезности теста в рабочей копии временно отключалась проверка `isBlank()`. `testDomainRules` завершился отказом именно в параметризованном тесте пустого имени. После возврата исходного условия два чистых запуска дали одинаковый зелёный результат.

Финальный исходник не содержит мутацию. Подробности и вывод: [проверка мутацией](docs/mutation-check.md).

## Наследуемое приложение

```shell
./gradlew run
./gradlew run --args="--smoke"
```

Локальные данные окна хранятся в `.lesson-data` и исключены из Git.
