# Протокол безопасного восстановления

## Подготовка

1. Закрыть приложение и все соединения с целевой базой.
2. Не удалять рабочую базу и единственный исправный снимок.
3. Создать новый пустой каталог для учебного восстановления.
4. Записать SHA-256 рабочей базы и резервной копии.

## Проверка снимка

1. Открыть копию отдельным соединением.
2. Выполнить `PRAGMA integrity_check` и получить единственный результат `ok`.
3. Проверить версию `schema_migration` и наличие таблицы `nutrition_plan`.
4. Прочитать количество и ключевые поля контрольных записей.

## Восстановление

1. Передать `restoreToNewDatabase` путь снимка и новый несуществующий файл.
2. Дождаться повторной проверки промежуточной копии.
3. Открыть восстановленный файл через `SqliteNutritionPlanRepository`.
4. Сравнить весь список планов с состоянием на момент снимка.
5. Убедиться, что более позднее изменение отсутствует. Это ожидаемая потеря в пределах RPO.

## Отрицательный сценарий

Повреждённый отдельный файл должен дать `BackupException` с причиной `INTEGRITY_FAILED`. Целевой файл после отказа отсутствует, а SHA-256 рабочей базы и хорошего снимка совпадает с исходными значениями.

## Команды

```shell
./gradlew testBackupRecovery
./gradlew runLessonDemo
```

Демонстрация создаёт все входы во временном каталоге и печатает фактические пути, версию схемы, число записей и итог сравнения.
